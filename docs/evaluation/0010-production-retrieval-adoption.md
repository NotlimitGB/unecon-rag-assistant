# Production Retrieval Adoption

## Starting state

Ветка `main`, исходный коммит Task020 `860c6c72ee8f6422ce6cbc54697425c2eba67542`, чистое дерево. SHA‑256 датасетов Task006 и Task010: `52de939e1ba13d1558c3e96fa6cec2cabdb69fca9158996aa1a4282d4167511e` и `11a284b4279f627ae787d0ec4777e0884733b4ec937d6658be3857c2dd15d0a4`.

## Adopted architecture

Один BGE‑M3 эмбеддинг запроса → производственный FAISS top‑20 + отдельный FAISS строк таблиц top‑5 → объединение 25 по dense score и ID → прежний BGE reranker всех 25 → жадный отбор с максимумом двух результатов на `(source_id, page_start)` PDF → итоговые top‑5. HTML не ограничивается. Настройки моделей и алгоритмы оценки score не изменены.

## Production artifact construction

Офлайн-сборка запросила три официальных PDF через существующий загрузчик и сверила их байты с нормализованными артефактами:

| Источник | SHA‑256 PDF | Строк |
|---|---|---:|
| `admission-capacity-pdf` | `748b164c0d1a5e7c82d7fcc4e8e417334be73f062b02c0bed5245e66ae2850c6` | 75 |
| `entrance-exams-list-pdf` | `656ccb00805760f0685c703587c0d5ae5f6dad9ca11ed098f72e6a2180f3d4d7` | 93 |

Всего получено **250** строк. Все ID, тексты, хеши, порядок и страницы совпали с локальными артефактами Task014. Размерность BGE‑M3 — 1024; табличный индекс связан с SHA‑256 `926c252595aad9b881eb5a72df639a78ec97eb068df27d4178f555bd03bb454a` основного индекса на **338** векторов. Извлечение выполнено PyMuPDF 1.28.2 со стратегией `lines_strict`. Эти числа проверены для миграции и не зашиты как постоянные ограничения сборки.

## Migration equivalence

Производственный top‑20 сохранён: оба канала используют один и тот же проверенный основной индекс и тот же эмбеддинг запроса; отдельный вызов dense mode остался доступен. Канонический `RetrievalService(mode="reranked")` воспроизвёл финальные ID, порядок, источник и страницу Task018 на **80/80** вопросах. Разница reranker score у каждого результата не превысила `1e-4`. Сравнение выполнено по каждой позиции, а не только по агрегатам.

## Critical probes

`ret-020` вернул страницу 4 на позиции **5**; `ret-044` — страницу 8 на позиции **5**; `ret-052` — HTML-источник `tuition` на позиции **3**. Обязательные строки `gen-008`, `gen-011`, `gen-021`, `gen-027` остались на позициях **1, 1, 2, 2** соответственно. Это подтверждено точным совпадением 80 списков с Task018.

## Public contract and runtime

Поля `RetrievalResponse` и `RetrievedChunk` не изменились: строка таблицы возвращает официальный URL, заголовок, ID источника, страницу и точный текст через общий контракт. `AnswerService` не требует особой ветви для таблиц. Инициализация ленивая, сессии и модели повторно используются. Runtime читает локальные проверенные индексы и артефакты без запросов к сайту источников. Отсутствующий или устаревший табличный индекс вызывает явную ошибку без fallback; явный dense mode независим от него.

## Latency

Диагностическая задержка полного локального поиска на 80 вопросах, в секундах: mean **7.104**, median **6.946**, p95 nearest-rank **7.646**, min **5.985**, max **22.034**. Индексы и модели были загружены по одному разу на прогон. Задержка зависит от нагрузки машины и не является критерием прохождения.

## Known follow-ups

Неоднозначность эталона `gen-008`, нехватка сводного контекста `gen-012`, замечания Task020 к генерации и цитированию, а также API и интерфейс остаются отдельными задачами. Для будущего интерфейса требуется явное уведомление:

> Ответ сформирован ИИ на основе официальных материалов СПбГЭУ. Для принятия важных решений рекомендуем уточнить информацию в приёмной комиссии.

В этой задаче интерфейс и генерация не запускались. Попадание в нужный источник не доказывает фактическую точность ответа.

## Verdict

**validated retrieval architecture adopted** — все проверки точной миграции и замороженных метрик прошли.
