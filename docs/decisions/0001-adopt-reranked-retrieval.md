# 0001 — Принять reranker для поиска приложения

## Контекст

Task006 установила базовые метрики плотного поиска BGE-M3 и FAISS на 80 вопросах по корпусу СПбГЭУ 2026 года. Task007 сравнила ту же выдачу с перестановкой её top-20 кандидатов моделью `BAAI/bge-reranker-v2-m3`.

## Решение

Основной сервис поиска приложения использует dense top-20 → BGE reranker → top-5. Плотный поиск остаётся явным диагностическим режимом и базовой линией оценки. Автоматического перехода на dense при ошибке reranker нет.

## Доказательства

В Task007 Primary Recall@1 вырос с 0,7000 до 0,7625, Primary MRR@5 — с 0,7525 до 0,8046, Primary Recall@5 — с 0,8625 до 0,8750, Page Recall@5 — с 0,7679 до 0,8393. Плотный Primary Candidate Recall@20 составил 0,9750.

## Последствия

Ранние позиции и поиск страницы улучшились, но работа требует второй локальной модели и добавляет задержку. Reranker не может восстановить нужный источник вне dense top-20. Гибридный поиск отложен: текущие результаты не обосновывают его сложность. Генерация ответов будет отдельным этапом.
