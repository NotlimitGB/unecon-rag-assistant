# ADR 0008 — Неизменяемые релизы корпуса и атомарный указатель

Дата: 2026-09-26.

## Причина

Task025 связал версии документов со снимками и индексами, но смена нескольких
рабочих каталогов не была одной атомарной операцией. Новая версия не должна
попадать в ответы до проверки всего корпуса; откат должен восстанавливать
проверенный набор без загрузки источников и повторных эмбеддингов.

## Решение

Релиз — полный локальный каталог с собственным реестром, всеми историческими
документами/снимками и активными чанками/индексами. `data/source_manifest.json`
остаётся reference/bootstrap-реестром. Единственная точка переключения —
`release_state.json`: generation, текущий ID, уникальная история, UTC-время и операция.

Incoming-пакеты проверяются всем набором до построения. Они содержат строгие
метаданные и ровно один HTML/PDF. Для замены обязательны активный предшественник,
прежнее семейство/год, новый ID и версия +1. Staging сохраняет историю и заново
строит активные чанки и оба индекса прежними алгоритмами. Таблицы читаются из
локальных снимков; зависимости между пакетами одного запуска запрещены.

Полная validation проверяет пары, чанки, индексы и выдачу 80 вопросов на основании
и кандидате одной парой моделей. Frozen gold проверяется относительно исторического
корпуса; метрики с прежними ID остаются диагностикой, не порогом принятия новой версии.
Успешная validation запечатывает digest релиза и точный SHA своего файла. Digest
охватывает постоянные метаданные и отсортированный инвентарь размеров/хешей, исключая
сам digest, sealing и ссылку на validation. Полный отчёт связан с digest обратно.

Все изменения сериализуются одним `O_CREAT | O_EXCL` lock. Publish требует ID,
expected-current, SHA validation и confirm, сверяет ID и generation основания.
После переноса в releases целостность проверяется ещё раз. Затем указатель записывается
через временный файл, flush, fsync и os.replace, после чего перечитывается.
Сбой до замены сохраняет старый указатель; orphan в releases можно опубликовать
повторно с теми же проверками. Rollback проверяет ранее опубликованную цель,
меняет только указатель и generation, сохраняет историю и новые релизы.

Сервис без явных путей закрепляет релиз при создании. Уже работающий экземпляр
не переключается посреди запроса; оператору явно требуется перезапуск backend.
Если указатель отсутствует/повреждён, health доступен, ответы дают прежний безопасный
503. Ошибка закреплена до создания нового сервиса; legacy fallback отсутствует.
При любых явных путях все пропущенные значения берутся из прежних defaults,
без смешивания с текущим релизом. Fake-фабрики остаются отдельной тестовой возможностью.

## Альтернативы и ограничения

- Замена нескольких каталогов по очереди отклонена: возможен смешанный корпус.
- Пересборка при откате отклонена: медленно и не гарантирует прежние артефакты.
- Горячее переключение существующего сервиса отклонено: требует отдельного жизненного
  цикла моделей и синхронизации запросов.
- Автоматическая публикация по метрикам отклонена: старые gold ID не описывают новые версии.
- Автоматическое удаление lock отклонено: возраст файла не доказывает отсутствие процесса.

Sealing — проверка целостности, не электронная подпись или защита от администратора,
который может переписать все файлы и хеши. Нет ОС-транзакции для всех файлов релиза:
атомарна только смена указателя в пределах локальной файловой системы. Релизы занимают
дополнительное место, автоматического удаления и UI управления документами нет.
Публичные ответы, алгоритмы, модели, prompt v2 и зависимости сохранены. Семантическое
качество новых материалов требует отдельной проверки человеком.
