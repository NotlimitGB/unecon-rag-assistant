# ADR 0005: HTTP API ответа приложения

## Контекст

Проверенные поиск и генерация доступны через CLI. Будущему frontend нужна стабильная граница приложения без зависимости от внутренних Python-модулей.

## Решение

Добавить синхронный `POST /api/v1/answer` над существующим `AnswerService`. Запрос содержит только строгую строку `question`: максимум 2000 символов до удаления крайних пробелов, затем проверка непустого значения. Ответ использует канонический `AnswerResponse` без изменения текста и цитат.

Один сервис создаётся в lifespan приложения, переиспользуется между запросами и закрывается при shutdown. Загрузка моделей и индексов остаётся ленивой. Health сохраняет смысл проверки работающего HTTP-процесса.

Оба доменных статуса, включая недостаточность сведений, возвращают HTTP 200. Ошибки запроса используют стандартный 422. Только `GenerationError` преобразуется в 503 с фиксированным безопасным сообщением. Журнал содержит типы и места ошибок без входных текстов и контекстов. Неожиданные ошибки не маскируются.

## Последствия

Frontend получает единый контракт с официальными цитатами. Telegram и MAX впоследствии смогут использовать ту же границу приложения; логика поиска и генерации остаётся в существующих сервисах.

Запрос синхронный и может выполняться несколько секунд, особенно при первой загрузке моделей. Потоковой передачи, состояния диалога и авторизации нет. CORS разрешает GET и POST только настроенному frontend origin.

## Отложено

Streaming, история диалогов, readiness зависимостей, rate limiting, авторизация, жизненный цикл документов, Telegram, MAX и уведомление об ИИ в будущем интерфейсе. Следующий этап — укрепление API и контролируемая сквозная проверка HTTP → RAG → Ollama.
